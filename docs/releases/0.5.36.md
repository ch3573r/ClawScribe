# ClawScribe 0.5.36

Changes from the published 0.5.35 release. See the
[GitHub release](https://github.com/ch3573r/ClawScribe/releases) for publication
status, installer assets, checksums, and the final build-validation record.
This document does not by itself certify a successful Windows build.

## Meeting Content And Notes

- Fixed a shared-summary chunking bug that could skip text after splitting at
  a sentence or word boundary. The chunker advances from the emitted boundary,
  preserves UTF-8 boundaries, and caps redundant overlap.
- The shared summary processor now stops on failed or empty chunk output rather
  than generating an apparently complete report from only the successful chunks.
  Empty transcript input is rejected before calling a provider; cancellation is
  preserved as cancellation. This is not resumable per-chunk retry.
- Extraction, combination, and final-report prompts now emphasize concise notes,
  explicit facts, negation and uncertainty, proposals versus agreed decisions,
  and unspecified owners/deadlines rather than invented assignments. These are
  prompt changes, not a measured reduction in model error. Dedicated
  OpenAI-compatible/Codex routes have separate implementations.
- Removed the transcript-view filler filter that could hide meaningful words
  such as German `er` and `um`. This fixes presentation, not stored transcript
  text that had already been recognized.
- Included the previously unreleased fix replacing length-derived Whisper
  confidence with mean model token probability and retaining nonempty short
  utterances rather than discarding them solely for a low confidence score.

## Transcript Usability

- Improved live-follow behavior when new transcript rows are tall; delayed
  scrolling is canceled on user interaction and cleanup.
- Added **Jump to live transcript** while reviewing older text during recording.
- Explicit navigation respects reduced-motion settings where applicable, and
  ordinary appends no longer repeatedly navigate to the same search result.
- Replaced nested transcript-row button semantics with a native timestamp
  playback button and associated custom speaker labels with their input.
- Speaker saves prevent duplicate submissions, show actionable failure feedback,
  and retain custom input until persistence succeeds.

## Resource Use And Credentials

- Hardware detection now reads physical memory through the existing `sysinfo`
  dependency, with the diagnostic environment override retained.
- Windows Whisper's adaptive thread policy is capped at four threads for detected
  memory values at most 8 GiB, or eight otherwise, leaving one logical thread
  outside that limit where possible. This is not a global app budget or a
  measured i5-1235U/8 GB performance guarantee.
- Best-effort diagnostic logging uses a bounded nonblocking queue, flushes quiet
  batches periodically, and avoids formatting disabled messages. This does not
  change audio capture queues to lossy channels.
- Included the previously unreleased fixes removing duplicate log targets and an
  unused audio-level metrics accumulator.
- Microsoft refresh-token file fallback on Windows is now protected with
  current-user DPAPI. Legacy plaintext fallback migrates on successful read;
  non-Windows platforms fail closed instead of writing a plaintext fallback.
  This does not encrypt the whole meeting database or recordings.

## Build And Release Engineering

- Aligned source/runtime version metadata to 0.5.36 without upgrading application
  dependencies. Only the application version entry changes in `Cargo.lock`.
- Hardened native command failure handling and required both current-version
  Windows installer formats. Retained frozen frontend and locked Cargo builds.
- Added source regression checks and native summary/resource tests to candidate
  staging, with an optional hosted Windows runner when a dedicated runner is
  unavailable.
- Added draft staging with exact build identity, checksums, and updater metadata;
  drafts do not advance the stable channel. Real dual-source recording acceptance
  remains a separate publication requirement.
- Updated README and build/release guides for actual credential storage, Windows
  toolchain/sidecar requirements, source versus published versions, and the limits
  of helper tests and low-memory tuning.

## Validation Boundaries

The implementation received frontend typechecking and 32 passing configured
frontend test cases. Isolated Rust checks passed 43 distinct tests (48 executions
because five chunker tests also ran through the processor harness). Those checks
used actual production module sources but stubbed the summary provider boundary;
frontend interaction checks used deterministic mocks rather than a browser.

The final GitHub Release must record the result of the full native Windows build
and selected native-crate tests separately. Do not equate isolated tests with
model inference, real meeting capture, or installer/update acceptance.

Real microphone-plus-system-audio capture, install/upgrade interaction, rendered
Windows accessibility/scaling, and sustained target-notebook performance were not
established by those source checks. Provider-wide context budgeting, resumable
summary reduction, and evidence-linked decisions/actions are not delivered by
this patch. Review generated notes before exporting.

Updater signing and Authenticode signing are different. Read the release's actual
signing status; an updater signature alone does not establish a trusted Windows
publisher. Never replace published binaries under an existing version tag.
