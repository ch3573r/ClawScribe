# ClawScribe 0.5.54 preview

This Windows GPU preview adds manual assistance during a recording, using the
configured answer provider and finalized transcript context. It builds on
[0.5.53](0.5.53.md). Stable remains 0.5.48.

## Manual live assistance

Expand the live-assistance panel during a recording to ask a question,
summarize so far or list open questions. Each action requires a click or
submission. The panel shows the provider, latest finalized transcript time and
incomplete-transcription state; delayed transcription does not represent the
current moment. Selected saved meetings and attached references can supplement
the recording context. These actions cover the latest ten minutes of finalized speech; complete meeting summaries are available after recording.

Live transcript sharing is a separate remembered setting, off until enabled.
Reference-document sharing is independent and resets for each live session.
Turning sharing off cancels active assistance. Audio-only recordings have no
live transcript; Built-in AI is unavailable during capture, with a saved-meeting
alternative after recording. Ollama runs separately and may compete for
notebook resources.

Live context includes finalized segments from the latest ten minutes, bounded
to 1,024 segments and 256 KiB. Partial text and earlier recording sessions are
excluded. Requests permit one active action and a 30-second deadline. Stop
invalidates the session and signals cancellation without awaiting the provider.
Live messages stay in memory and clear on Stop; they are not a new saved history
or part of portable backups. Background indexing, model loading and parsing
yield to recording. No automatic requests or additional capture pipeline are
introduced.

Recording and assistance state use the native producer identity to reject
delayed events from an earlier recording. Stop invalidates pending startup
checks immediately, and metadata lookups stay bounded during event bursts.
An oversized assistance answer reports an error while preserving earlier
messages.

If startup status verification fails, the panel shows that failure separately
and Retry status rechecks the current recording and assistance owners. Recovery
requires the current session pair; Stop or a newer recording invalidates an old
retry. Retrying metadata does not restart audio or submit an assistance question.
Pause/Resume keeps that recovery usable and preserves the current paused state.

Known preview limitation: the recording context can make two overlapping
metadata reads during reload/startup recovery. Both retain session guards;
the assistance store uses one lane. This adds bounded IPC work, with no extra
provider request or capture work. A shared context lane remains follow-up work.

The sharing control also has a deferred label-association issue when its Home
and Settings instances are rendered together. The underlying permission is shared.

## Screens to check

- Home/recording: manual panel, sharing, selected references, answers/citations,
  latest finalized time, provider failures, Cancel and stopping state.
- Settings → Meeting memory: remembered live transcript-sharing permission, off by default.
- Navigation during recording: one state owner, no duplicated actions or stale
  messages after Stop and a second recording.

Check light/dark/accent themes, focus, Enter/Shift+Enter and layouts at 1000 px
and wider. Exact-build installed checks remain pending.

## Validation and updates

The published verification record identifies exact designated-runner frontend,
native, lifecycle/privacy/cancellation and archive results. Realistic one-hour
fixtures exercise bounded context and delayed transcription; synthetic tests
do not establish physical recording quality or provider factual accuracy.

Exact-build dual-source saved playback, clean Stop, a second recording,
real-provider workflows and a release-like two-hour enabled/disabled notebook
comparison remain pending. The comparison must record engine/model/language,
active backend, memory trend, backlog, request times and Stop timing. Upgrade,
update/signature acceptance and sustained device/sleep-wake recovery also remain
pending before stable promotion. The owner's 0.5.53 audio confirmation applies
to that earlier build and does not certify 0.5.54 live-assistance performance.

The installer/runtime/updater version is 0.5.54. Stage a draft, verify both
installers, detached Tauri signatures, checksums, build identity and updater
manifest, then publish as a prerelease with latest=false. Stable remains
0.5.48. Enable **Include prereleases** or install manually; drafts are excluded
from updates. Finish recording and saving before installation. Tauri updater
signatures are separate from Windows publisher signing. The release profile is
windows-gpu: Whisper Vulkan and ONNX/sherpa DirectML; meeting embeddings use CPU.
