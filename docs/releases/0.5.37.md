# ClawScribe 0.5.37 Preview

This Windows x64 preview makes the recording and meeting-quality review fixes
available for manual installation and evaluation. Download the NSIS setup EXE
or MSI from the [0.5.37 release](https://github.com/ch3573r/ClawScribe/releases/tag/v0.5.37).
Publication status, final build identity, signatures, and checksums are recorded
with those assets. A source version alone does not establish release readiness.

## Recording And Recovery

- Stage captured mixed audio independently of AAC encoding. Preserve accepted
  spool chunks until final audio and metadata are saved, including an unconsumed
  tail during recovery.
- Bound capture buffering, stop repeated encoding attempts after failure, and
  finalize through a staged file with encoder deadlines.
- Save separate audio-failure and incomplete-transcription outcomes. Live and
  saved-meeting notices explain when to inspect audio and retranscribe. Automatic
  notes are withheld when recovery is needed.
- Keep actual recording state visible when live transcription fails. Stopping
  capture and waiting for remaining recognition are distinct operations.
- Preserve nonempty short utterances and represent missing confidence as
  unavailable, including missing Whisper token probabilities.

## Notebook Resources And Existing Meetings

- Prepare import and retranscription audio on disk and load bounded speech
  segments, avoiding whole-recording decoded buffers in these paths.
- Run native inference outside the async executor. Coordinate recording, batch
  work, diarization, model changes, and built-in local summaries through a shared
  exclusive job gate.
- Reject empty or incomplete retranscription before replacement, and retain the
  prior transcript as a database revision when replacement succeeds. A revision
  restore UI is not included.
- Preserve SQLite WAL/SHM data when opening or migrating the database fails.
  Provider credentials migrate to provider-specific OS credential references;
  Windows fallback uses current-user DPAPI and fails closed.

## Meeting Notes And Interface

- Apply finite context budgets and hierarchical reduction across summary paths,
  including compatible APIs and bundled Codex. Reject failed, empty, or
  nonconverging reductions instead of presenting incomplete notes as complete.
- Search the entire transcript for chat-relevant excerpts and disclose selected
  context. Lexical retrieval can still miss synonyms or dispersed evidence.
- Support smaller native windows, collapse navigation on narrow layouts, and
  add named onboarding controls and progress semantics.
- Remove sensitive meeting/provider content from reviewed diagnostics and honor
  Microsoft Graph's full numeric `Retry-After` delay.

## Installation And Update Behavior

The normal build uses `windows-gpu`: Whisper Vulkan and ONNX/sherpa DirectML are
separate acceleration paths. Runtime acceleration must be checked in the app;
successful compilation does not establish an active GPU backend. The installer
still requires a supported GPU driver or official Vulkan loader at startup.

The source, installer, and updater metadata use version `0.5.37`. This is a
GitHub prerelease for manual installation, so the stable updater continues to
offer `0.5.36`. The preview's `latest.json` identifies its own NSIS asset and
signature without changing the stable endpoint. Any later changed build must
advance the numeric version again.

Use a backed-up installation when checking upgrade behavior and retain existing
meeting data. Review the release's signing status: Tauri updater signatures
protect update artifacts; they are not Windows Authenticode publisher signing.

## Validation And Remaining Acceptance

The application fixes passed frontend typechecking, 34 frontend tests, a
production frontend build, native Windows checking with `windows-gpu`, and
447 native library tests on the designated build machine. Three existing tests
were ignored, and three audio-device tests were excluded because that machine
has no audio endpoints. Optimized executable builds also passed. The release
workflow separately builds the installers and runs its required native
release-profile regression groups before staging assets.

These checks do not establish transcription accuracy or target-notebook speed.
Before stable promotion, complete the [real-device acceptance checks](../windows-release.md#required-real-device-acceptance):
dual-source Teams/Webex capture, playable saved audio including the final words,
clean stop and a second recording, install/upgrade persistence, native keyboard
and scaling behavior, multilingual recognition and note quality, and sustained
i5-1235U / 8 GB memory/backlog measurements.

Long-recording diarization still materializes decoded audio. Parakeet cannot be
forcibly interrupted inside its current native call; a following job waits for
that call to finish. A process crash can lose the in-memory fraction of the
current one-second capture batch, and storage failures cannot recover samples
that never reached disk. Full-repository Rust formatting retains pre-existing
differences in unchanged files; the edited Rust files pass formatting checks.

No real capture-smoke confirmation or stable-readiness claim is made for this
preview. Review generated decisions, owners, deadlines, and quantities against
the source transcript and audio.
