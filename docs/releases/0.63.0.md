# ClawScribe 0.63.0 preview

This preview continues the fixes from 0.62.0. It hardens recording against
stuck devices and full disks, shows real audio levels, keeps stored keys inside
the app's core, and finds interrupted recordings on disk.

## Recording

- **Device reconnect.** Reconnecting a device held a lock that every other
  recording action needed, so the app could hang. The reconnect no longer holds
  it. If an audio driver stops answering, Stop gives up after 20 seconds with a
  message and the recording keeps running; try Stop again.
- **One source lost.** When a reconnect fails for the microphone or for the
  meeting audio, the other source keeps recording and a notice names the one
  that is missing.
- **Disk space.** A recording does not start when less than about 1.6 GB is free
  where recordings are saved. During a recording, a notice appears once when
  less than about 780 MB is left.
- **Real levels on Home.** During a recording, Home shows the microphone and the
  meeting audio as two level meters. "No microphone signal yet" appears when the
  microphone has produced no signal at all for ten seconds after a start or a
  resume.
- **A failed Stop is shown.** Before, the app displayed "Waiting for
  transcription" for up to a minute and then silently returned to recording.
- **Call end during a reconnect.** The automatic stop for a detected call is no
  longer lost when a device reconnect is running at that moment.

## Interrupted recordings

Recovery used to list only recordings that the window had noted in its own
storage. It now also looks in the recording folders, so it finds recordings
that were interrupted before the first transcript line, audio-only recordings,
and recordings started without the window.

**Settings → General → Storage** shows an **Interrupted recordings** row with
the number found. It reopens the recovery dialog. Nothing is deleted without
your confirmation. **Keep, do not ask again** hides a recording from the list;
**Show kept** in that row brings it back.

A recording that stopped normally but was never saved to the library is not
detected.

## Keys and tokens

- The app's interface no longer receives stored API keys or tokens. A stored
  key is shown as saved, with its last four characters when it is at least 20
  characters long, and with **Replace** and **Remove**.
- A stored key is only sent to the address it was saved for. After changing the
  address of the custom provider, of hosted transcription or of OpenClaw, the
  key has to be entered again.
- Replacing or removing a key deletes its entry in the Windows credential
  store. Entries left behind by earlier versions are not removed, because they
  cannot be listed safely.
- A new key must have at least 8 characters.

## Files and folders

The core no longer acts on a path just because the interface sent it. A file or
folder is used when you chose it in a dialog that the core opened, or when the
app created it itself.

- The recordings folder is chosen with **Choose folder** under **Settings →
  Recording**. A folder that was configured before this version stays in use,
  including one on a network share, and so do the folders that hold your
  existing meetings. A drive root, a share root, a system folder,
  and the Documents, Desktop, Downloads and AppData folders themselves are
  refused; a subfolder of Documents is fine. If the stored folder is refused,
  recordings go to the default folder and Settings says so.
- Opening a recording folder, saving a recording and deleting a meeting's files
  only work on folders that the app created for that meeting.
- Audio import, reference documents, backup, restore, Word export and the
  hosted transcription test use the file you picked in the dialog for that
  action. Dropping an audio file on the window still works.
- The Claude Code program must be a local file named `claude`. A project-local
  copy inside a `node_modules` folder is refused.
- The Codex profile folder is chosen with **Choose folder** and must be local
  and empty, new, or already used by ClawScribe. A custom folder set in an
  earlier version stays in use.
- The interface can no longer write the app's settings files or open file
  dialogs on its own. It can still read files in the app's data folder, which
  holds the meeting database, the logs and the settings files; stored keys are
  not in those files. It can also start the installation of a signed update
  and restart the app.

## Settings

- GPU use, the separate transcription process, cloud transcription, source
  labels, the transcription language and the recording-started notice are now
  stored by the core and loaded
  before anything can record. Before, they lived in the window's storage and
  the core used defaults until the window had loaded. Existing values are taken
  over once. Cloud transcription stays off unless it was switched on.
- Call detection and automatic summaries are still stored by the window,
  because the window runs them.

## Other changes

- If the meeting database cannot be opened, a dialog names the data and log
  folders and the app closes. Before, it closed without a message.
- A summary that runs in the background is shown as running when you open its
  meeting, and an empty summary offers **Generate summary** directly.
- When the meeting list cannot be loaded, an error with **Retry** is shown
  instead of an empty library.
- Sidebar search waits until you stop typing and ignores late results from an
  earlier search.
- The Home dialog for the transcription language and a setting for confidence
  indicators that had no effect were removed. The language is under
  **Settings → Transcription**.
- 65 commands and 27 interface files that nothing used were removed.

## Updating and testing

The Windows x64 installer and updater version is **0.63.0**. In **Settings →
General → Updates**, enable **Include prereleases**. Finish recording and
saving before installing. The stable channel continues to offer 0.5.58.

These changes were checked with automated tests. None was exercised in an
installed build, with real audio devices or with real keys. Real-device checks
remain pending: a reconnect during a recording, a start on a nearly full disk,
the level meters, recovery of an interrupted recording from disk, an update
with keys saved by an earlier version, and the items listed in the
[0.62.0 preview notes](0.62.0.md).
