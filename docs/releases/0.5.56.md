# ClawScribe 0.5.56 preview

This Windows GPU preview simplifies the compact meeting chat and removes reference
documents that no meeting uses any more. It builds on [0.5.55](0.5.55.md). Stable
remains 0.5.48.

## Meeting chat

The compact corner chat now keeps the conversation first. Question scope and
reference files no longer sit above the messages.

- A slim **Context** control under the title shows the current scope, for example
  "This meeting · 2 files". It opens a panel with **This meeting only** or **Other
  saved meetings**, a searchable meeting picker with a height limit, project
  filters behind **Filters**, and the reference files with **Add file**.
- A paperclip beside the question field attaches a file to the meeting using the
  same local extraction as before, including cancellation and error messages.
  Selected files appear as removable chips above the field.
- **Use selected references for answers** appears in Context only when a file is
  selected and the answer provider is not Built-in AI. Sending excerpts to an
  external provider stays off by default for each conversation.
- **Search mode** moved into the chat's **More options** menu.
- The empty chat offers three suggested questions. They fill the question field
  and never send anything.
- A reference action that finishes after you switched scope no longer cancels an
  unrelated answer.

The Meeting memory page is unchanged in this release.

## Reference documents are removed with their last meeting

Earlier previews left a reference document, its extracted text and its original
file in app data after you deleted its only meeting or detached it from its only
meeting. Nothing in the app could reach those files, and portable backups still
included them.

- Deleting a meeting now deletes references used only by that meeting, including
  the original file, even when you keep the recording files. References shared
  with another meeting are kept. Answers that depended on a deleted reference are
  invalidated and their saved content is cleared. A failure to remove an original
  file appears in the deletion warnings.
- Detaching a reference from its last meeting deletes it and its original file.
- At startup the app removes references left behind by 0.5.53 to 0.5.55 when no
  recording or import is active. It never waits for the database, so a busy
  launch skips the cleanup and the next launch tries again. Unknown files in the
  reference folder are kept for at least 24 hours before cleanup.
- Portable backups include only references attached to a meeting.

## Other fixes

- The live transcript sharing switch on Home and in Settings no longer share one
  element id, so a label click cannot toggle the other switch.

## Validation, limitations and updates

Frontend validation passed typecheck, the public-repository safety scan, the UI
conventions check and 391 frontend tests. The Rust changes were validated on the
designated runner, including new tests for meeting deletion, detach, the startup
cleanup and backup. The release verification record identifies the exact packaged
commit, native validation, assets, checksums and updater manifest.

The chat layout was checked visually in a browser against a mocked backend. It has
not been checked in an installed build, so theme, focus and portal behavior remain
unverified there.

Extraction limits, provider transport, evidence maps and recording paths are
unchanged. The limitation from [0.5.54](0.5.54.md) that recording-context
recovery can overlap at most two metadata reads remains. The sharing-switch
label issue listed there is fixed.

Exact-build dual-source playback, clean Stop and a second recording, upgrade,
installed update and signature acceptance, provider factual accuracy, and
comparable two-hour enabled and disabled live-assistance performance remain
pending before stable promotion. Earlier audio acceptance does not certify this
build.

Enable **Include prereleases** or install manually; drafts are excluded from
